# Codex Review

## Findings

1. **High: the investigation proves the v10 boundary, but not the claimed cause.** `planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:11-13` and `planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:264-286` attribute the discrepancy to an April 2024 vs October 2024 WEO documentation lag. The evidence actually shown in `planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:21-61` proves only that the current workbook's macrofiscal-fed formulas extend through 2029 and baseline calculations begin in 2030. It does not show workbook provenance, WEO-vintage metadata, or a release-history link tying SPEC to April 2024 and v10 to October 2024. Alternative explanations not ruled out include a workbook-specific manual extension, a mixed definition of `WEO_MAX_YEAR` ("last fully WEO-driven year" vs "last macrofiscal year present"), or general source drift unrelated to WEO vintage. For the IMF meeting, present "observed workbook behavior" separately from "suspected reason."

2. **High: `WEO_MAX_YEAR = max(macrofiscal.years)` is not robust enough as stated.** `planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:65-71` and `planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:288-329` promote `max(macrofiscal["years"])` as the implementation rule. That is only safe if required series are contiguous and complete at the boundary for the selected country. The document itself shows module-specific dependence on different boundary series: GDP and debt formulas in Baseline (`planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:50-59`), deflator growth in Inflation (`planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:133-156`), and the nominal-rate anchor in Interest Rate (`planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:213-218`). If macrofiscal data are ragged, if years are non-contiguous, or if one required series stops earlier than the others, raw `max(year)` can overstate the usable WEO horizon. The recommendation should require validation: contiguous annual years, no country-specific gaps at the tail, and a single last common year across the WEO-driven inputs the module actually uses. If that invariant fails, the engine should raise a boundary-validation error instead of guessing.

3. **High: the document overstates the case for `CLIMATE_START_YEAR = WEO_MAX_YEAR + 1`.** `planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:79-121` is enough to establish that climate impacts start in 2030 in v10 and that `PROJ_START = 2031` is inconsistent with the workbook. It is not enough to establish the structural rule later recommended at `planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:290-295` and `planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:331-337`. The cited evidence is at least as consistent with a fixed calendar start: the scenario annotation literally says "from 2030" (`planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:79-82`), the formulas are keyed to the 2030 column (`planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:86-91`), the User Guide says "starting in 2030" (`planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:99-104`), and Discrete Risks also begins in 2030 (`planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:104`). Those are not independent confirmations of a dynamic rule; they may all reflect a single hardcoded calendar-year design. The safer conclusion is: "2030 is verified for v10; dynamic linkage to the WEO horizon is unproven." To test the hypothesis, compare another workbook vintage, inspect whether the first climate-adjusted column moves when the macrofiscal horizon changes, or ask IMF what actually controls the first divergence year.

4. **Medium: the inflation-fallback conclusion is plausible, but the negative proof is incomplete.** `planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:129-166` rules out visible formulas in `C24:C25`, visible lookup tables, and visible advisory automation in the User Guide. That supports "no obvious automated fallback." It does not document checks for hidden sheets, defined names, external workbook links, or other hidden assets that could store country defaults. The specific VBA concern is weak because the workbook is described as `.xlsx` at `planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:5`; if that extension is accurate, VBA is not the likely mechanism. The stronger unresolved question is whether defaults are hidden workbook data or simply saved literals that analysts overwrite manually. Also, the move from "no automated fallback" to "the engine should raise an error if the user does not provide values" (`planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:164-166`) is a product choice, not a parity finding.

5. **Medium: several IMF questions are framed as confirmation of the current theory rather than neutral elicitation.** Questions 1-3 and 6 in `planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:303-314` embed assumptions that are still disputed: that v10 specifically uses the October 2024 WEO, that the right implementation is dynamic `WEO_MAX_YEAR`, and that climate start should move with the WEO horizon. That makes them too leading for a meeting intended to surface hidden design rules. I would reframe them as:
- "What determines the last macrofiscal year in each release: the WEO vintage, workbook maintenance choices, or module-specific availability?"
- "Is the first climate-impact year fixed at 2030, or is it derived from the last macrofiscal year?"
- "When country selection changes, what populates inflation/productivity/interest defaults: formulas, hidden tables, saved literal values, or manual analyst entry?"
- "For the nominal interest-rate anchor, should parity use the last available macrofiscal year, the last fully WEO-driven year, or a fixed calendar year?"

6. **Medium: the document is missing the guardrail an autonomous agent most needs.** The strongest risk is not that an agent will miss the 2029/2030 handoff; it is that the agent will generalize v10 observations into universal implementation rules. `planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:65-71`, `planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:117-121`, `planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:288-337`, and `planning/investigations/WEO-BOUNDARY-INVESTIGATION.md:386-388` state runtime derivation and `WEO_MAX_YEAR + 1` too categorically. The most likely mistake is that an agent will encode raw `max(year)` and dynamic climate start, then silently mishandle a future vintage with ragged macrofiscal coverage or a still-fixed 2030 climate start. The missing guardrail is an explicit confidence taxonomy:
- `Verified in v10 workbook`
- `Inferred from current evidence`
- `Requires IMF confirmation before encoding as a generic rule`
The implementation notes should also require runtime validation of contiguity/completeness at the WEO boundary.

## Bottom line

The evidence documented here is sufficient to say that, in workbook v10, the macrofiscal-fed baseline formulas run through 2029 and climate scenarios first diverge in 2030. It is not sufficient to say that the root cause is definitively an April-vs-October WEO documentation lag, that `max(macrofiscal.years)` is always the right runtime rule, or that climate start is structurally `WEO_MAX_YEAR + 1` rather than fixed at 2030.
