# Oracle Packet: inflation

## Economic Logic

The inflation module projects the GDP deflator growth rate from the historical period (2009-2028) through the end of the projection horizon (2099). In Q-CRAFT, "inflation" specifically means the GDP deflator growth rate, NOT consumer price inflation (CPI). The GDP deflator is used because it captures the broadest measure of price changes in the economy and better reflects the full tax base for a government.

**Why it matters:** Inflation is the bridge between real GDP and nominal GDP. Nominal GDP is the tax base -- it determines government revenue in local currency units. Without an inflation projection, the tool cannot compute nominal GDP, revenue, expenditure in levels, interest expenditure, or debt dynamics. The inflation module is thus a prerequisite for every downstream fiscal calculation.

**The core assumption is macroeconomic stability:** Q-CRAFT assumes that in the long run, countries converge toward a stable inflation rate consistent with the Central Bank's inflation target. The user specifies a "start" rate (reflecting WEO-period inflation) and an "end" rate (reflecting the long-run target). The transition between these two rates uses a **logistic convergence function** -- the same functional form used in the productivity module, but with a faster convergence (turning_point=5 vs turning_point=15 for productivity).

**Historical values (years <= WEO_MAX_YEAR):** These are derived from macrofiscal data as the year-over-year growth rate of the GDP deflator index. Specifically: `inflation(t) = (deflator(t) / deflator(t-1)) * 100 - 100`.

**Projected values (years > WEO_MAX_YEAR):** These are generated by the logistic convergence function using the user-supplied `start` and `end` parameters.

**Important nuance from the golden master data:** For Uganda with the default parameters (start=3.5, end=3.5), every projected year from 2029 onward shows exactly 3.5. This is because when start == end, the logistic function collapses to a constant -- no convergence is needed. This is the most common use case: the user sets both start and end to the Central Bank's target, and inflation is flat for the entire projection period.

## Key Formulas

### 1. Historical Inflation (years 2009 through WEO_MAX_YEAR)

Inflation is the GDP deflator growth rate, derived from the macrofiscal data:

```
inflation(t) = (gdp_deflator(t) / gdp_deflator(t-1)) * 100 - 100
```

Where `gdp_deflator` is an index (base year 2015=100 typically) from the IMF WEO database. This computation happens in the Macrofiscal sheet and is pulled into the Inflation sheet.

For Uganda, the golden master shows values like:
- 2009: 17.43% (high deflator growth)
- 2010: 2.16%
- 2023: 3.95%
- 2028: 4.52% (last WEO year)

### 2. WEO Boundary Year Treatment

The year immediately after the WEO horizon (year WEO_MAX_YEAR + 1, which is 2029) is where the transition from historical to projected inflation begins. However, in the golden master for Uganda, 2029 already shows the WEO-derived value (4.83%), while 2030 onward shows 3.5. This suggests:

- Years up to and including some WEO boundary use macrofiscal-derived deflator growth.
- The SPEC says WEO_MAX_YEAR = 2028, so years > 2028 use the logistic convergence.
- The golden master shows 2029 = 4.833... (still looks like a WEO-derived value) and 2030 = 3.5 exactly.

**Critical observation from golden master:** The Uganda golden master shows the transition happening at year 2030 (the first year showing exactly 3.5), which means years 2009-2029 use macrofiscal-derived values, and years 2030-2099 use the logistic convergence output. This aligns with PROJ_START = 2031 being the first "projection year" in some contexts, but inflation projection may start one year earlier (2030) or the WEO data extends through 2029 for the deflator.

**Resolution:** The macrofiscal parquet data contains GDP deflator values through 2028 at minimum (the WEO horizon). The deflator growth rate for year 2029 can be computed if the deflator index for 2029 is available in the WEO data. Looking at the golden master, 2029 shows 4.833... which is a non-round number, clearly derived from actual deflator data rather than the logistic function. So the historical period extends through 2029 for the deflator (WEO provides data through at least 2029 for some variables).

### 3. Logistic Convergence Function (projection period)

For years beyond the WEO horizon:

```
counter = year - WEO_MAX_YEAR    (1-indexed: counter=1 for WEO_MAX_YEAR+1)
rate = 0.5                        (FIXED, not user-modifiable)
turning_point = 5                  (FIXED for inflation; compare: 15 for productivity)

inflation(year) = start + (end - start) * ((1 / (1 + exp(-rate * (counter - turning_point)))) ^ rate)
```

Where:
- `start` = Dashboard B24 (default 3.5 for Uganda)
- `end` = Dashboard B25 (default 3.5 for Uganda)
- `exp` = the natural exponential function
- `rate` = 0.5 (the slope parameter, rose-pink highlighted in spreadsheet, should NOT be changed)
- `turning_point` = 5 (the inflection point in years after WEO_MAX_YEAR)

**When start == end:** The formula reduces to `start + 0 * (anything) = start`, so inflation is constant at the start/end value for the entire projection period. This is why Uganda's golden master shows exactly 3.5 from 2030-2099.

**When start != end:** The logistic function provides an S-shaped transition. With turning_point=5, the transition is rapid -- most of the convergence happens within ~10 years of the WEO horizon. This is faster than productivity (turning_point=15) because the assumption is that Central Banks achieve their inflation targets more quickly than structural productivity convergence occurs.

### 4. The Full Formula Expanded

```python
import math

def logistic_convergence(counter, start, end, rate=0.5, turning_point=5):
    """Compute inflation for a single projection year.

    counter: years since WEO_MAX_YEAR (1-indexed)
    start: inflation start rate (%)
    end: inflation end rate (%)
    rate: slope parameter (fixed at 0.5)
    turning_point: inflection point (fixed at 5 for inflation)
    """
    logistic_base = 1.0 / (1.0 + math.exp(-rate * (counter - turning_point)))
    return start + (end - start) * (logistic_base ** rate)
```

## Gotchas

### 1. Logistic Convergence, NOT Linear Interpolation
The PYTHON_REIMPLEMENTATION_GUIDE.md incorrectly states "Linear interpolation from start to end" for productivity (and by implication inflation). This is WRONG. Both use the logistic convergence function. The SPEC and the Excel formulas are authoritative -- the logistic formula with `rate=0.5` is the correct implementation. An agent that implements linear interpolation will fail golden master tests whenever `start != end`.

### 2. Turning Point Differs Between Inflation and Productivity
- **Inflation:** `turning_point = 5` (fast convergence)
- **Productivity:** `turning_point = 15` (slow convergence)

An agent that copies the productivity logistic function and forgets to change the turning point will get wrong results for inflation when start != end. This is easy to miss because for Uganda's defaults (start=3.5, end=3.5), the turning point does not matter -- both values produce 3.5.

### 3. The `rate` Parameter Has Dual Use
In the logistic formula `(1 / (1 + exp(-rate * (counter - turning_point)))) ^ rate`, note that `rate` appears TWICE:
- Once as the slope of the logistic curve (inside the exp)
- Once as the exponent of the result

Both uses are the SAME value (0.5). This is easy to misread as two different parameters. The SPEC formula: `f(t) = start + (end - start) * ((1 / (1 + exp(-rate * (t - turning_point))))^rate)` confirms this.

### 4. Counter is 1-Indexed from WEO_MAX_YEAR
The counter variable starts at 1 for the first year after WEO_MAX_YEAR, NOT at 0. If `WEO_MAX_YEAR = 2028`:
- Year 2029: counter = 1
- Year 2030: counter = 2
- Year 2099: counter = 71

Getting the off-by-one wrong shifts the entire S-curve by one year.

### 5. GDP Deflator vs CPI
Q-CRAFT uses the GDP deflator, NOT CPI. The User Guide (p.28, footnote 14) explicitly states: "Q-CRAFT uses GDP deflator and, for the long run and in the baseline scenario, assumes stable economic conditions and no structural breaks, so that CPI inflation and the GDP deflator converge." An agent that looks for CPI data will find the wrong series.

### 6. Historical Inflation Requires Deflator INDEX, Not Growth Rate
The macrofiscal data stores the GDP deflator as an INDEX (level). Historical inflation must be computed as `(index(t) / index(t-1)) * 100 - 100`. If the parquet data already contains a pre-computed growth rate column, verify it matches this formula. If it only contains the index, you must compute the growth rate yourself. The first year of inflation (2009 if the index goes back to 2008, or 2002 per the Inflation sheet in Excel) depends on how far back the index data goes.

### 7. Default Parameters Hide Bugs
Uganda's defaults have `start = end = 3.5`, which means every projected year equals exactly 3.5 regardless of the logistic function implementation. This makes it impossible to detect bugs in the logistic convergence using Uganda alone with default parameters. To test the logistic function, you MUST either:
- Use a country where start != end, OR
- Use non-default parameters where start != end

### 8. The Inflation Module is Deceptively Simple
The golden master for Uganda is just two columns (years, inflation) with historical values followed by a flat 3.5. An agent might be tempted to hard-code or shortcut. But the logistic convergence must work correctly for ALL parameter combinations -- this is what makes the function generalizable across countries and user inputs.

### 9. Inflation is Exogenous to Climate Scenarios
Climate change affects productivity and GDP in Q-CRAFT, but NOT inflation. The same inflation trajectory is used for the baseline and all 6 climate scenarios. This is a deliberate simplification per the User Guide (p.28): "with the external and monetary sectors exogenous, Q-CRAFT abstracts from these possibilities."

### 10. The WEO Boundary Year (2028/2029) Needs Careful Handling
Looking at the golden master:
- Year 2028: inflation = 4.5185... (macrofiscal-derived)
- Year 2029: inflation = 4.8337... (macrofiscal-derived)
- Year 2030: inflation = 3.5 (logistic convergence, which is just the constant `start` value)

This suggests the macrofiscal deflator data extends through 2029 (WEO projections typically go a few years beyond the current year). The Python implementation must correctly detect where macrofiscal data ends and projection begins. If the deflator index is available through year N, then inflation can be computed through year N (as growth from N-1 to N), and the logistic convergence starts at year N+1.
