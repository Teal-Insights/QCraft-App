# Oracle Packet: inflation

## Economic Logic

The inflation module projects the GDP deflator growth rate from the historical period (2009-2029) through the end of the projection horizon (2099). In Q-CRAFT, "inflation" specifically means the GDP deflator growth rate, NOT consumer price inflation (CPI). The GDP deflator is used because it captures the broadest measure of price changes in the economy and better reflects the full tax base for a government. The User Guide (p.28, footnote 14) states: "Q-CRAFT uses GDP deflator and, for the long run and in the baseline scenario, assumes stable economic conditions and no structural breaks, so that CPI inflation and the GDP deflator converge." This means the distinction matters for the historical period, but by assumption CPI and GDP deflator converge in the long run.

**Why it matters:** Inflation is the bridge between real GDP and nominal GDP. Nominal GDP is the tax base -- it determines government revenue in local currency units. Without an inflation projection, the tool cannot compute nominal GDP, revenue, expenditure in levels, interest expenditure, or debt dynamics. The inflation module is thus a prerequisite for every downstream fiscal calculation.

**The core assumption is macroeconomic stability:** Q-CRAFT assumes that in the long run, countries converge toward a stable inflation rate consistent with the Central Bank's inflation target. The user specifies a "start" rate (reflecting WEO-period inflation) and an "end" rate (reflecting the long-run target). The transition between these two rates uses a **logistic convergence function** -- the same functional form used in the productivity module, but with a faster convergence (turning_point=5 vs turning_point=15 for productivity).

**Historical values (years where macrofiscal deflator data exists):** These are derived from macrofiscal data as the year-over-year growth rate of the GDP deflator index. Specifically: `inflation(t) = (deflator(t) / deflator(t-1)) * 100 - 100`.

**SOURCE CONFLICT -- WEO boundary for inflation:** The SPEC defines `WEO_MAX_YEAR = 2028` and says inflation projection starts "beyond WEO max year." However, the golden master shows 2029 = 4.833... (a macrofiscal-derived value, not a logistic output) and 2030 = 3.5 (the first logistic year). The resolution is that the macrofiscal GDP deflator INDEX extends through at least 2029, allowing deflator growth to be computed through 2029. The engine should use macrofiscal-derived values for all years where deflator index data is available, and start the logistic convergence at the first year after data runs out. For the current dataset, this means historical through 2029 and logistic from 2030. The counter for the logistic function should still be `year - WEO_MAX_YEAR` (see Gotcha #4), which means 2030 gets counter=2. See "WEO Boundary Year Treatment" section below for full details.

**Projected values (years after macrofiscal data ends):** These are generated by the logistic convergence function -- the SAME function used in the productivity module, but with `turning_point=5` instead of `turning_point=15` for faster convergence. The rationale: Central Banks are assumed to achieve their inflation targets more quickly than structural productivity convergence occurs.

**Important nuance from the golden master data:** For Uganda with the default parameters (start=3.5, end=3.5), every projected year from 2030 onward shows exactly 3.5. This is because when start == end, the logistic function collapses to a constant -- no convergence is needed. This is the most common use case: the user sets both start and end to the Central Bank's target, and inflation is flat for the entire projection period.

## Key Formulas

### 1. Historical Inflation (years 2009 through last available deflator year)

Inflation is the GDP deflator growth rate, derived from the macrofiscal data:

```
inflation(t) = (gdp_deflator(t) / gdp_deflator(t-1)) * 100 - 100
```

Where `gdp_deflator` is an index (base year 2015=100 typically) from the IMF WEO database. This computation happens in the Macrofiscal sheet and is pulled into the Inflation sheet.

For Uganda, the golden master shows values like:
- 2009: 17.43% (high deflator growth)
- 2010: 2.16%
- 2023: 3.95%
- 2028: 4.52%
- 2029: 4.83% (last macrofiscal-derived year)

### 2. WEO Boundary Year Treatment

**SOURCE CONFLICT (consolidated):** The SPEC defines `WEO_MAX_YEAR = 2028` (derived from `max(macrofiscal.years)`) and says inflation projection uses logistic convergence "beyond WEO max year." Taken literally, this means 2029 should be the first logistic year (counter=1). However, the golden master contradicts this:

| Year | Golden Master Value | Source |
|------|-------------------|--------|
| 2028 | 4.5185... | Macrofiscal-derived (deflator growth) |
| 2029 | 4.8337... | Macrofiscal-derived (non-round, clearly not logistic output) |
| 2030 | 3.5 exactly | Logistic convergence (constant because start==end) |

**Two distinct concepts are being conflated:**
1. **"Macrofiscal worksheet coverage"** -- the years for which the GDP deflator INDEX exists in the macrofiscal data. The index extends through 2029, allowing deflator growth to be computed through 2029.
2. **"Engine projection start"** -- the year where the logistic convergence function takes over. For inflation, this is 2030 (the first year without macrofiscal deflator data to derive growth from).

**Implementation rule (golden-master-driven):** Use macrofiscal-derived deflator growth for all years where the deflator index is available. Start the logistic convergence at the first year AFTER the deflator data ends. For the current WEO vintage, this means:
- Historical: 2009-2029 (macrofiscal-derived)
- Logistic: 2030-2099 (using counter = year - WEO_MAX_YEAR, so 2030 gets counter=2)

**Why this differs from productivity:** The productivity module starts logistic convergence at year 2029 (counter=1, the year after WEO_MAX_YEAR=2028). For inflation, the macrofiscal deflator INDEX extends one year further than the nominal "WEO_MAX_YEAR," pushing the transition to 2030. This is a data-availability difference, not a formula difference.

### 3. Logistic Convergence Function (projection period)

**SAME function as productivity, different `turning_point`.** The inflation module uses the identical logistic convergence formula as the productivity module. The only parameter difference is `turning_point=5` (inflation) vs `turning_point=15` (productivity). If you have already implemented `logistic_convergence()` for productivity, reuse it here with the different turning_point.

For years beyond the macrofiscal deflator data (2030+ for the current WEO vintage):

```
counter = year - WEO_MAX_YEAR    (1-indexed: counter=1 for WEO_MAX_YEAR+1, but see note below)
rate = 0.5                        (FIXED, not user-modifiable)
turning_point = 5                  (FIXED for inflation; compare: 15 for productivity)

inflation(year) = start + (end - start) * ((1 / (1 + exp(-rate * (counter - turning_point)))) ^ rate)
```

**Note on counter for inflation:** Because macrofiscal deflator data extends through 2029 (one year past WEO_MAX_YEAR=2028), the first logistic year is 2030, which gets counter=2 (not counter=1). Year 2029 would be counter=1, but it is still macrofiscal-derived. This means the logistic curve effectively "skips" counter=1 for inflation. This does not affect the formula -- just be aware that the first counter value used in practice is 2.

Where:
- `start` = Dashboard B24 (default 3.5 for Uganda testing)
- `end` = Dashboard B25 (default 3.5 for Uganda testing)
- `exp` = the natural exponential function
- `rate` = 0.5 (the slope parameter, rose-pink highlighted in spreadsheet, should NOT be changed)
- `turning_point` = 5 (the inflection point in years after WEO_MAX_YEAR)

**When start == end:** The formula reduces to `start + 0 * (anything) = start`, so inflation is constant at the start/end value for the entire projection period. This is why Uganda's golden master shows exactly 3.5 from 2030-2099.

**When start != end:** The logistic function provides an S-shaped transition. With turning_point=5, the transition is rapid -- most of the convergence happens within ~10 years of the WEO horizon. This is faster than productivity (turning_point=15) because the assumption is that Central Banks achieve their inflation targets more quickly than structural productivity convergence occurs.

### 4. The Full Formula Expanded

```python
import math

def logistic_convergence(counter, start, end, rate=0.5, turning_point=5):
    """Compute inflation for a single projection year.

    counter: years since WEO_MAX_YEAR (1-indexed)
    start: inflation start rate (%)
    end: inflation end rate (%)
    rate: slope parameter (fixed at 0.5)
    turning_point: inflection point (fixed at 5 for inflation)
    """
    logistic_base = 1.0 / (1.0 + math.exp(-rate * (counter - turning_point)))
    return start + (end - start) * (logistic_base ** rate)
```

## Gotchas

### 1. Logistic Convergence, NOT Linear Interpolation
The PYTHON_REIMPLEMENTATION_GUIDE.md incorrectly states "Linear interpolation from start to end" for productivity (and by implication inflation). This is WRONG. Both use the logistic convergence function. The SPEC and the Excel formulas are authoritative -- the logistic formula with `rate=0.5` is the correct implementation. An agent that implements linear interpolation will fail golden master tests whenever `start != end`.

### 2. Turning Point Differs Between Inflation and Productivity
- **Inflation:** `turning_point = 5` (fast convergence)
- **Productivity:** `turning_point = 15` (slow convergence)

An agent that copies the productivity logistic function and forgets to change the turning point will get wrong results for inflation when start != end. This is easy to miss because for Uganda's defaults (start=3.5, end=3.5), the turning point does not matter -- both values produce 3.5.

### 3. The `rate` Parameter Has Dual Use
In the logistic formula `(1 / (1 + exp(-rate * (counter - turning_point)))) ^ rate`, note that `rate` appears TWICE:
- Once as the slope of the logistic curve (inside the exp)
- Once as the exponent of the result

Both uses are the SAME value (0.5). This is easy to misread as two different parameters. The SPEC formula: `f(t) = start + (end - start) * ((1 / (1 + exp(-rate * (t - turning_point))))^rate)` confirms this.

### 4. Counter is 1-Indexed from WEO_MAX_YEAR
The counter variable starts at 1 for the first year after WEO_MAX_YEAR, NOT at 0. If `WEO_MAX_YEAR = 2028`:
- Year 2029: counter = 1
- Year 2030: counter = 2
- Year 2099: counter = 71

Getting the off-by-one wrong shifts the entire S-curve by one year.

### 5. GDP Deflator vs CPI
Q-CRAFT uses the GDP deflator, NOT CPI. The User Guide (p.28, footnote 14) explicitly states: "Q-CRAFT uses GDP deflator and, for the long run and in the baseline scenario, assumes stable economic conditions and no structural breaks, so that CPI inflation and the GDP deflator converge." An agent that looks for CPI data will find the wrong series.

### 6. Historical Inflation Requires Deflator INDEX, Not Growth Rate
The macrofiscal data stores the GDP deflator as an INDEX (level). Historical inflation must be computed as `(index(t) / index(t-1)) * 100 - 100`. If the parquet data already contains a pre-computed growth rate column, verify it matches this formula. If it only contains the index, you must compute the growth rate yourself. The first year of inflation (2009 if the index goes back to 2008, or 2002 per the Inflation sheet in Excel) depends on how far back the index data goes.

### 7. Default Parameters Hide Bugs
Uganda's defaults have `start = end = 3.5`, which means every projected year equals exactly 3.5 regardless of the logistic function implementation. This makes it impossible to detect bugs in the logistic convergence using Uganda alone with default parameters. To test the logistic function, you MUST either:
- Use a country where start != end, OR
- Use non-default parameters where start != end

**Recommended test:** Create a parametric test with `start=8.0, end=2.0` and verify that:
1. The first logistic year is closer to `start` than `end`
2. By ~10 years after the WEO boundary, inflation is close to `end`
3. The transition is monotonic (no overshooting)
4. The turning_point=5 produces faster convergence than turning_point=15 would

This catches bugs in the logistic formula, the counter indexing, and the turning_point parameter that are invisible with start==end.

### 8. The Inflation Module is Deceptively Simple
The golden master for Uganda is just two columns (years, inflation) with historical values followed by a flat 3.5. An agent might be tempted to hard-code or shortcut. But the logistic convergence must work correctly for ALL parameter combinations -- this is what makes the function generalizable across countries and user inputs.

### 9. Inflation is Exogenous to Climate Scenarios
Climate change affects productivity and GDP in Q-CRAFT, but NOT inflation. The same inflation trajectory is used for the baseline and all 6 climate scenarios. This is a deliberate simplification per the User Guide (p.28): "with the external and monetary sectors exogenous, Q-CRAFT abstracts from these possibilities."

### 10. The WEO Boundary Year (2028/2029) Needs Careful Handling
See the consolidated "WEO Boundary Year Treatment" section under Key Formulas. In summary:
- Year 2028: inflation = 4.5185... (macrofiscal-derived)
- Year 2029: inflation = 4.8337... (macrofiscal-derived -- deflator index data extends past WEO_MAX_YEAR)
- Year 2030: inflation = 3.5 (first logistic year, counter=2)

The Python implementation must correctly detect where macrofiscal deflator INDEX data ends and use that as the boundary. If the deflator index is available through year N, then inflation can be computed through year N (as growth from N-1 to N), and the logistic convergence starts at year N+1. Do NOT hard-code 2029 as the boundary -- derive it from the data extent.
