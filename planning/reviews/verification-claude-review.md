# Verification Strategy Review — Claude Opus

## Summary

The verification prompt is well-structured for an overnight autonomous run and will produce valuable parity data. However, it has a critical gap: it only verifies 4 final fiscal outputs and completely skips all intermediate computations (GDP, demography, productivity, inflation, interest rates), leaving it vulnerable to the exact "right answer, wrong reason" failure mode that the oracle review process was designed to catch. The WEO vintage alignment risk is acknowledged implicitly but has no concrete mitigation step. The prompt is 80% ready — the fixes below are surgical and won't add scope.

## Top 3 Recommendations

1. **Add intermediate output checks for GDP, interest rate, and inflation** — at minimum for Phase 1's 3 countries. This is the single highest-value change. Without it, compensating errors are invisible and you could demo wrong numbers that happen to produce correct ratios. The data is already available from `run_pipeline()`.

2. **Add a WEO-period sanity check in Phase 1** — compare 2023-2029 historical values between Excel and Python for Uganda. These must match exactly (same source data). If they don't, the verification is compromised at the foundation. This takes 5 minutes of agent time and catches the most catastrophic failure mode.

3. **Fix the Phase 1 Uganda gate to use golden master CSVs with ±0.1pp tolerance** — the existing golden masters at `tests/golden_masters/final/uganda.csv` are the ground truth. The agent should compare xlwings output against THOSE, not against the Python engine. This tests the cell mapping AND the engine simultaneously, and the tight tolerance catches small mapping errors.

## Missing Investigation Threads

1. **Countries with negative debt-to-GDP.** The baseline applies `max(0, debt_to_gdp)` (`fiscal.py:212`). Countries that achieve zero debt will have their debt floored, meaning revenue/expenditure ratios diverge from a "true" zero-debt economy. The verification should flag countries where `debt_to_gdp` hits 0 and note whether Excel also floors it.

2. **Countries where the fiscal rule switches trajectory mid-projection.** The fiscal rule triggers on `rising AND above_target` or `falling AND below_target` (`fiscal.py:242-244`). A country that oscillates around the debt target will have the rule toggle on/off, creating complex path dependence. The sensitivity test should include a debt target close to a country's current debt (e.g., Uganda at ~51% with target=50) to exercise this.

3. **Interest rate mode sensitivity.** Phase 3 only varies debt_target, fiscal_rule, and expenditure_rigidity. It never changes the interest rate mode (`"Nominal interest rate"` vs `"Interest-growth differential"` vs `"Real interest rate"`). The IGD mode uses prior-year GDP growth (`interest_rate.py:74`) — a bug here would be invisible with the default nominal mode. Add at least one param combo with `select_rate="Interest-growth differential"`.

4. **Excel recalculation ordering.** When you change multiple inputs (country + debt_target + fiscal_rule) in Excel, the recalculation may be order-dependent if VBA macros or circular references are involved. Phase 3 changes multiple params per combo. The prompt should specify: set country first, wait for recalc, THEN set params, wait again. Not all at once.

5. **SIDS with unusual GDP structures.** Maldives is included (good), but no test exercises what happens when GDP is very small (nominal_gdp < 1B USD). Division by very small GDP in percent-of-GDP calculations could amplify floating-point errors beyond the ±0.5pp tolerance. Worth noting in the report if SIDS systematically show larger deviations.

6. **Countries not in the parquet data but in Excel.** The prompt handles "NOT_IN_EXCEL" but not the reverse — Excel has a country that our parquet extraction missed. `get_country_list()` in `data_loader.py:63-68` intersects all 4 datasets, so missing from ANY source means the country is excluded. The Phase 0 discovery should extract Excel's full country list and compare it to `get_country_list()` output, flagging any countries available in Excel but not in Python.
