# Building the companion guide

Maintainer notes for `docs/companion-guide`. Nothing here is reader material: the
guide itself keeps source, vintage and limitation beside each figure, and sends
the build mechanics here. That split came out of the GPT ergonomics review of 31
August 2026 (Artifact 2, finding 9), which found the parameters chapter telling a
ministry economist which script drew a figure and where the repository puts it,
at the exact point the reader was being asked to choose an assumption.

This file is deliberately not a chapter. It is not listed in `_quarto.yml`, so it
reaches no sidebar, no PDF and no search index, and it sits with the guide's
other maintainer documents: `country-coverage.md`, `parameter-data.md`,
`data-vintages.md`, `export-contract.md`.

## Rendering

Two profiles, and a third for authoring. Point Quarto at a browser that is not
the desktop Chrome first: with Teal's own Chrome open, the mermaid diagrams in
Module 1 never get a debugging port and the render sits at file 3 of 12 with
no error (run 15 report, section 10).

    export QUARTO_CHROMIUM="$HOME/Library/Caches/ms-playwright/chromium-1234/chrome-mac-arm64/Google Chrome for Testing.app/Contents/MacOS/Google Chrome for Testing"
    quarto render docs/companion-guide                      # the open edition
    quarto render docs/companion-guide --profile brand      # the house edition
    quarto render docs/companion-guide --profile authoring  # with the notes visible

The open edition is self-contained: the three open faces in `fonts/open/` are
bundled and declared in `_custom.css`, so a rendered page fetches no font from
anyone's server. The `brand` profile adds `_brand-fonts.css`, which declares the
licensed Klim faces served from tealinsights.com; where those files are absent
every stack falls through to the open faces. No word, number or figure differs
between the two.

The `authoring` profile sets `authoring-notes: true`, which restores the blocks
`_authoring-notes.lua` otherwise deletes. Its output must never be published.

Two scripts run after every render, wired into `project: post-render:`:

- `scripts/clean_search_index.py` strips the inlined SVGs' text nodes from
  `search.json` and splits the glossary into one entry per term.
- `scripts/check_publication_safety.py` fails the build if authoring-only content
  reached the HTML, the PDF or the index, or if a marker in the source escaped
  the `authoring-note` class. Under the authoring profile it checks the source
  only, since that build renders the notes on purpose.

## Authoring-only blocks

A block carrying the `authoring-note` class is production apparatus and is
deleted from the syntax tree before it can reach any output:

    ::: {.callout-warning .authoring-note}
    ## WIDGET-TODO: expenditure rigidity
    ...
    :::

`DRAFT FOR TEAL` callouts are not authoring notes. They are visible by
instruction until Teal's editorial pass, and they must never carry the class.

When a note is the only thing qualifying visible prose, the qualification moves
into the reader's text before the note is hidden. Two blocks were treated that
way in the CC-25 round, and the rule holds for the next one: hiding a caveat
silently upgrades unverified prose to apparently-verified.

## Which script draws which figure

Every fragment under `figures/` opens with a `<!-- Generated by ... -->` comment
naming its generator, and that comment is the authority. The table repeats it so
that removing the script names from the guide's colophon loses nothing.

| Generator | Fragments |
|---|---|
| `scripts/build_course_map.py` | the eleven `_course-map-*` fragments (m0, m1, m1-dock, m2, m2-base, m2-dock, m2-full, m3, m4, m5, m6) |
| `scripts/build_exhibits.py` | the eighteen hand-drawn exhibits: `_m0-paths`, `_m1-ten-minutes`, `_m1-parity`, `_m2-cold-open`, `_m2-equation-annotated`, `_m2-equation-growth`, `_m2-growth-stack`, `_m2-primary-balance`, `_m2-scoreboard`, `_m2-weo-handoff`, `_m2-interest-rules`, `_m2-climate-panels`, `_m3-controls`, `_m4-seven-steps`, `_m4-fan-readings`, `_m5-debt-floor`, `_m5-exclusions`, `_m6-packet` |
| `scripts/build_parameter_context.py` | the five source-data figures in Module 3: `_param-country-context`, `_param-demography-variants`, `_param-productivity`, `_param-inflation`, `_param-rigidity-record`. Drawn from the same Parquet inputs the Explorer runs on |
| `scripts/build_preface_figures.py` | `_preface-elevator`, `_preface-questions` |
| `scripts/build_app_screenshots.py` | the five Explorer captures: `_screenshot-m1-analysis-gap`, `_screenshot-m2-baseline-reconciliation`, `_screenshot-m3-rigidity-compare`, `_screenshot-m4-baseline`, `_screenshot-m4-climate-index` |
| `scripts/capture_both_ways_shots.py` | the preface's side-by-side pair and the four workbook shots in Appendix A, captured from the live deployment and the posted v10 workbook file |

Each figure fragment carries a print variant under
`::: {.content-hidden when-format="html"}`, so the PDF gets a raster and the HTML
gets the inline SVG. The `<figcaption>` survives into the PDF as the figure
caption, which is what allows the guide's prose to stop restating what each map
lights.

Rebuilding the screenshots needs the Explorer served first, then:

    uv run --package qcraft-engine python scripts/build_app_facts.py
    uv run --no-project --with playwright python3 scripts/build_app_screenshots.py

## Branch state, and why the guide stopped naming paths

As of 31 August 2026 the restructured guide is on `feat/lane4-course` and not on
`main`. On `main`, `docs/companion-guide` still holds the older three-part
structure (`part1-policy.qmd`, `part2-using.qmd`, `part3-codesign.qmd`), and
neither the five `build_*.py` scripts nor `docs/country-coverage.md` exists.
`packages/qcraft-engine` does exist on `main`, tests included.

That is why the guide now cites the repository by URL and by the outcome a reader
can check, rather than by filename. A relative repository path is a build
instruction wearing a source's clothes: it does not resolve from where a reader
is standing, and until this branch merges it does not resolve at all. The rule
outlasts the merge. Filenames are a maintainer's index.

Two pointers were removed from reader prose on that ground, and both facts they
carried live on:

- The colophon's five script names. The reader claim they were serving, that the
  screenshots are real captures rather than mockups and that the book builds from
  its repository with no network access, stays in the colophon.
- `docs/country-coverage.md` in the Module 3 country-coverage callout. Every
  quantifier in that callout stays, and the reader's two working checks stay with
  them: the Explorer says on screen when a country is refused, and the IMF User
  Guide, Section II.B, describes what is loaded for each country.

## Open editorial questions

Both were `TODO` callouts visible to readers before the CC-25 round. The
maintainer half is here; the reader-facing half stayed in the guide.

- **Two sets of Uganda numbers in Module 4.** The Explorer's own run on WEO
  October 2024 at the tool's defaults ends around 127 percent of GDP under Hot +
  Unadapted, while the module's prose quotes the published 2023 workshop figures,
  an earlier vintage with its own parameter choices, ending at 66 percent under
  Hot. Both are correct for what they are. Whether to keep both in one module,
  and which leads, is an editorial call for review.
- **The common-errors list in Module 6.** It comes from the misconceptions the
  course was designed against rather than from watching people make them. The
  redesign plan makes a pilot with two or three target-profile testers
  non-negotiable, and that pilot's error log should replace the list.
- **The Module 5 comparison exercise** would be usable in a 20-minute workshop
  breakout with two or three verified country pairs, run and checked against the
  current data vintage. It needs a real run rather than an assumption about which
  pairs work.
- **The Module 4 perspective figure.** The second framing needs a checked
  comparator before it ships: 4 percent of Uganda's GDP expressed against a named
  line of the approved budget, sourced to the Approved Estimates for the relevant
  year. Do not ship an approximate comparison in a document aimed at the ministry
  that publishes the actual number.
- **Workshop materials.** The live sessions need artefacts this guide does not
  contain: breakout task cards, the anonymous poll items, the peer-review sheet
  derived from the capstone rubric, and the two follow-up emails (Day 3 retrieval
  question, Week 2 application check). Tracked separately from the book.
