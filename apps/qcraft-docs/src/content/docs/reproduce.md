**An Explorer build needs the country payloads as well as the source code.** npm installs JavaScript dependencies. It does not supply the 525 country files that the browser fetches. Keep the source revision, package lockfile and pinned input archive together.

## Build the Explorer from an exact source revision

**Use Node 25.9.0, npm 11.12.1 and Python 3.14.6 for the tested setup.** The extraction recipe requires Python 3.12 or newer for the `tarfile` data filter. The source below identifies the full-WEO release `qcraft-tool-2026-09-05`. Use Git for the source checkout and GitHub CLI for the archive download, or save the [input archive](https://github.com/Teal-Insights/QCraft-App/releases/download/qcraft-tool-2026-09-05/qcraft-tool-inputs-2026-09-05.tar.gz) from the [release page](https://github.com/Teal-Insights/QCraft-App/releases/tag/qcraft-tool-2026-09-05) into `setup-inputs/`.

```sh
git clone https://github.com/Teal-Insights/QCraft-App.git qcraft-explorer
cd qcraft-explorer
git checkout --detach a6313ad7f8f38e174bd38c89e3419ee1be79cda9
mkdir -p setup-inputs
gh release download qcraft-tool-2026-09-05 --repo Teal-Insights/QCraft-App --pattern qcraft-tool-inputs-2026-09-05.tar.gz --dir setup-inputs
```

**Verify the archive before extracting or building.** Expected SHA-256: `9054a3257ca143f8d5e7e6180b39e4b1de46d04bc2598f13637554acf49341ac`. The archive is 19,342,520 bytes. It supplies 525 country payloads across three revision sets, their indexes and manifests, cached WEO source inputs and the two official reference files. Its 535 content-checksum entries cover those inputs; `README.md` and `SHA256SUMS` bring the archive to 537 files. Only the payloads are needed for the Explorer build. The current operating companion is generated by `docs/tool-guide/build.py`; it also needs the unchanged `imf-qcraft-tool-v10.xlsx` and `imf-qcraft-user-guide-v10.pdf` in `docs/tool-guide/resources/`. Preserve those separately checksummed sources when reproducing the complete site.

```sh
python3 - <<'CHECK'
from pathlib import Path
import hashlib, tarfile
archive = Path('setup-inputs/qcraft-tool-inputs-2026-09-05.tar.gz')
expected = '9054a3257ca143f8d5e7e6180b39e4b1de46d04bc2598f13637554acf49341ac'
assert hashlib.sha256(archive.read_bytes()).hexdigest() == expected
with tarfile.open(archive) as bundle:
    bundle.extractall('setup-inputs/unpacked', filter='data')
CHECK
```

**Copy payloads into the three revision directories before building.** The committed indexes supply the country lists. The prebuild staging script requires the ignored country JSON files next to them.

```sh
python3 - <<'STAGE'
from pathlib import Path
import hashlib, shutil
root = Path('setup-inputs/unpacked')
for line in (root / 'SHA256SUMS').read_text().splitlines():
    digest, rel = line.split(maxsplit=1)
    assert hashlib.sha256((root / rel.strip()).read_bytes()).hexdigest() == digest
for vintage in ('weo-2024-10', 'weo-2026-04', 'weo-2026-04-full-horizon-v1'):
    files = sorted((root / 'payloads' / vintage).glob('*.json'))
    assert len(files) == 175
    dest = Path('data/vintages') / vintage / 'json'
    assert (dest / 'index.json').read_bytes() == (root / 'indexes' / vintage / 'index.json').read_bytes()
    assert (Path('data/vintages') / vintage / 'manifest.json').read_bytes() == (root / 'manifests' / f'{vintage}.json').read_bytes()
    for file in files:
        shutil.copy2(file, dest / file.name)
STAGE
npm ci --prefix apps/qcraft-web
VITE_BASE_PATH=./ npm --prefix apps/qcraft-web run build
```

**The current operating companion has a separate build step.** Copy the two reference downloads from the same checked archive, then build its six pages. The complete release assembly places this `site/` output at `/QCraft-App/guide/`, the app at `/QCraft-App/explorer/`, and this separately built docs package at `/QCraft-App/docs/`. It also preserves the historical March guide and older URLs.

```sh
python3 - <<'GUIDE'
from pathlib import Path
import shutil
sources = Path('setup-inputs/unpacked/references')
dest = Path('docs/tool-guide/resources')
dest.mkdir(parents=True, exist_ok=True)
for name in ('imf-qcraft-tool-v10.xlsx', 'imf-qcraft-user-guide-v10.pdf'):
    shutil.copy2(sources / name, dest / name)
GUIDE
python3 docs/tool-guide/build.py
```

**Build output uses relative asset and data paths.** The `./` base makes the bundle portable. Serve it over HTTP at `/QCraft-App/explorer/` using the arrangement below to preserve the published route.

## Serve a prepared distribution without a network

**Prepare the distribution while online, then serve its local files.** A prepared release must include the Explorer bundle, all three complete payload sets, file checksums and a short startup note. It must be extracted and checked before entering the training room. Record the exact source and archive used for your build. Earlier offline evidence is not a new check of this revision.

```sh
mkdir -p offline-root/QCraft-App/explorer
cp -R apps/qcraft-web/dist/. offline-root/QCraft-App/explorer/
python3 -m http.server 8080 --bind 127.0.0.1 --directory offline-root
```

Open `http://127.0.0.1:8080/QCraft-App/explorer/`. The local HTTP server needs no Internet connection. Browser `file://` loading is unsupported because module scripts and fetch requests require HTTP behavior.

**Test both modes before relying on offline access.** With external requests disabled, select Uganda in Current, then Verified, and confirm that results differ. Save a run, change a setting, import it and confirm country, mode, parameters and recorded input/policy identity restore. Import an older Current file separately and confirm that changed-data/calculation warnings appear rather than a claim of exact replay. Also select a country that has not previously been opened, to confirm that every country payload is present. A warm browser cache is not proof of a complete offline bundle.

## Preserve the inputs with a result

**Save the run file beside the input archive and release manifest.** Include the exact engine commit and the payload SHA-256, plus any report and workbook export. New run files identify the input revision, calculation policy, input hash and selected timing but do not embed input data or result series. Read any restore warnings before comparing the result to an earlier report.
